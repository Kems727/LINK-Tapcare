# TapCare - NFC Health Access Card (class demo)

Static website (no server). Blue theme. Sample logo: replace `assets/logo.svg` with your own (keep the file name).

## Put it online with GitHub Pages (no coding)
1. Sign in at github.com > **New repository** > name it `tapcare` > **Public** > Create.
2. **Add file > Upload files**: drag in EVERYTHING inside this folder (including the `.nojekyll` file, `css`, `js`, `assets`, `data`, `index.html`, `cards.html`). Commit.
3. **Settings > Pages > Build and deployment**: Source = *Deploy from a branch*, Branch = `main`, folder `/ (root)` > Save.
4. After ~1 minute your site is at `https://<your-username>.github.io/tapcare/`.
5. Open `https://<your-username>.github.io/tapcare/cards.html`: it shows the two cards and the exact web addresses to write into the NFC cards.

## Write the NFC cards with an iPhone
Use blank NTAG215 (or 213/216) cards and the free **NFC Tools** app: Write > Add a record > URL/URI > paste the address from `cards.html` > Write, then hold the card to the top of the iPhone.
iPhone XS or newer reads the card with the screen on (Background Tag Reading) and opens Safari at the verification screen.

## How the security works
- The card stores only a web address with an ID number. No medical data.
- Every record is encrypted (AES-256-GCM, keys from PBKDF2-SHA256 250,000 rounds) before it is saved. Patient PIN or staff password unlocks it. Staff share a master key wrapped per person.
- Roles: patient (own record) / doctor + nurse (clinical) / helpdesk (directory, register, verify; clinical masked) / admin (roster, attendance board, audit log; no records).
- 5 wrong attempts = 60 s lock. 5 min idle = auto sign-out. Keys live in memory only (refresh = sign in again). Every access is audit-logged.

## Honest limits of a GitHub Pages demo
- No real server database: new registrations, notes and attendance are saved in the visitor's own browser, not shared across devices. For true shared data use Firebase/Supabase behind `js/store.js`.
- Role rules are enforced in the browser. A production system must enforce them on a server.
- Anyone can download the encrypted files. Demo passwords are published on purpose; never reuse this for real patients.
- A copied NFC card works until the PIN/password step. Real systems add card-level cryptography (e.g. NTAG 424 DNA).
- All hospitals, numbers and medical details are fictional samples. GitHub Pages free plan needs a public repo, so the sample patient name is public.

`data/` is generated by the private tool (not in this folder). Do not publish the private tool: it holds the plain sample data and passwords.
